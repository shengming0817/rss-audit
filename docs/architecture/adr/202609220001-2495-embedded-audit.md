# #2495 嵌入式审计边界

状态：已采纳。本决定与 #2496 的 V1 协议在同一变更交付。

## 原则

彻底：Audit 协议、后续 PostgreSQL schema/adapter 与 HTTP adapter 只有 rss-audit 一个 owner。
历史 Audit 只提供失效案例，不复制 Identity actor、HMAC 链、查询 DTO、assembly 或管理角色。

不向后兼容：V1 是 fresh persisted wire。没有旧数据导入、旧类型别名、双写、兼容 decoder、旧路由或
legacy feature。未知 record version、tag 与尾随字段默认拒绝；breaking 演进使用新 record version。

优雅简洁：首期只有 provider-free core。完整性直接组合 rss-ledger；不建立 repository/provider 平台、
动态注册、中央事件总线、全局 assembly、多数据库框架或自研密码链。

## Owner 与来源保证

`rss-audit-core` 拥有 V1 值类型、规范字节、ledger 映射和闭合错误。#2497 的 PostgreSQL adapter
拥有 fresh schema、RLS、事务 append/query、数据库记录时间和 commit evidence。#2500 的 HTTP adapter
拥有私有 DTO 与租户内查询映射。

来源产品拥有事件含义、event/source/actor 的真实性、动作词汇、业务授权以及是否必须产生记录。
宿主持有认证授权、密钥和轮转、保留/hold、迁移执行、数据库角色与生命周期。

两种来源保证不可混同：

1. 业务同事务 append 将业务效果与审计记录放入同一租户事务；只有 commit ACK 才形成 evidence。
2. Outbox 投影只在来源业务与 Outbox 已原子提交后可靠、幂等写入 Audit；它不与原业务表同事务。

`AuditEventV1` 不含 recorded time。recording boundary 注入数据库权威时间并生成 `PreparedAuditV1`；
prepared bytes、ledger entry 和 HMAC 验证都不是 durable commit evidence。commit unknown 必须原样重试
同一 prepared request，不能生成新 ID、时间或 payload。

## 威胁模型

| 威胁 | V1 处置 | 非保证 |
|---|---|---|
| 来源或 actor 伪造 | 字段受界、来源 contract 精确携带 | core 不认证来源或授权 |
| 跨租户混淆 | tenant 同时绑定 record 与 ledger，验证时复核 | 类型本身不证明调用方有租户权限 |
| 字段拼接碰撞 | 域标记、固定顺序、长度前缀和 golden | 不提供内容机密性 |
| 重放或同 ID 漂移 | 同 ID 同 bytes replay；任一变化 conflict | 不承诺 exactly-once |
| Debug/序列化泄漏 | 私有敏感 wrapper、脱敏 Debug、无 serde/Display | accessor 的合法使用仍由调用方负责 |
| decoder 资源耗尽 | 分配前校验字段和总预算、checked arithmetic | 不代替外层请求预算 |
| 版本降级 | 未知 record version/tag/尾随数据拒绝 | 来源 contract 的准入由 adapter 精确决定 |
| staged 冒充提交 | core 不定义 committed receipt | #2497 T2 才能证明提交结果 |
| 丢事件或截尾 | ledger 验证给定窗口 | HMAC 不证明完整历史、WORM 或透明日志 |
| 持钥方篡改 | 宿主持有并限制密钥 | HMAC 不提供对持钥方不可抵赖 |
| 时间伪造 | occurred 是来源陈述；recorded 由 recorder 注入 | 两者不证明跨机器真实顺序 |

## V1 记录与完整性

action 是来源 contract 拥有的 opaque token，不建立全产品枚举。actor/resource 只是稳定引用。
payload 是有界精确字节，类型保护 Debug，不证明内容已经正确脱敏。禁止无界 metadata map。

每租户使用 `rss.audit.v1` ledger chain；record ID 为 `v1:{source}:{event}`，payload 为完整 Audit V1
canonical bytes。rss-ledger 继续唯一拥有 HMAC、sequence、key identity、窗口验证和 ledger idempotency。

## 兼容与范围

Rust API 与 persisted wire 是两个独立兼容轴。本包首次发布前为 uncommitted；V1 wire 一经消费即按
精确字节保护。当前不实现 PostgreSQL、HTTP、Identity 投影、MDM 切换、Web 迁移、跨租户全局读、
生产 T3、WORM、透明日志、历史导入或密钥轮转。
